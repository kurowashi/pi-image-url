# ADR 0001: 画像は ImageContent として直接返す

## 状況

画像URLをモデルに見せる方法が3つありました。

1. ツール結果の content に画像ブロックを直接入れる。
2. 一時ファイルに保存し、画像ブロックとパスを返す。
3. 一時ファイルに保存してから `ctx.executeTool("read")` を呼ぶ。

Pi はツール結果の画像を `normalizeToolResultImages` で正規化し、必要なら自動リサイズしてから履歴に入れます。

## 決定

1 を採用します。`read_image_url` は取得したバイト列を base64 にし、`{ type: "image", data, mimeType }` を content に返します。

## 理由

- 結果は Pi が正規化・自動リサイズするため、ツール側の追加処理が要りません。
- 一時ファイルを作ると、作成場所・後始末・衝突を誰が管理するかが増え、単機能の範囲を超えます。
- `read` はローカルパス専用なので、ネスト呼び出しにしてもモデルに届く結果は同じ画像で、間接層とコード量だけが増えます。

## 却下した代替

- 一時ファイル + パス返却: 後続ターンで `bash` や `@path` から再利用できますが、その用途が必要になった実例がありません(YAGNI)。
  ファイルのライフサイクル管理も増えるため、必要になった時点で別の機能として検討します。
- 一時ファイル + `read` ネスト: 結果は同じ画像です。ダウンロード経路とテスト面が二重になり、得るものがありません。
- Pi 本体の `read` に URL 対応を入れる: このリポジトリの範囲外です。まず拡張で必要性を検証し、実測で寄与が示せてから本体に提案します。
